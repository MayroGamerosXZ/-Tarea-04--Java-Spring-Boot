🎬 Guion del Video: ThunderMax

Instrucciones: Este es el texto sugerido que puedes leer mientras muestras tu pantalla grabando el video. Puedes poner esta ventana en la mitad de tu pantalla para usarla como teleprompter. Hemos incluido los comandos y los momentos exactos donde debes dar clic.

Escena 1: Inicio y Arranque del Sistema

En Pantalla: Muestra IntelliJ IDEA o tu terminal abierta en la carpeta del proyecto.
Tú (Hablando al micrófono): "Hola, mi nombre es Mayro Gameros. Como parte del curso de Análisis de Sistemas, les presento mi proyecto 'ThunderMax', una API REST diseñada para gestionar una ferretería guatemalteca. El sistema fue construido utilizando arquitectura de capas con Java y Spring Boot 3."
Tú: "Lo primero que haré será levantar mi base de datos PostgreSQL utilizando Docker. En mi terminal ejecuto el comando:"
Acción: Escribe y ejecuta en la consola docker compose up -d
Tú: "Con la base de datos levantada en el puerto 5433 para evitar conflictos, ahora ejecuto el backend mediante el botón de Play en IntelliJ IDEA."
Acción: Haces clic en el botón de Play (▶️) en IntelliJ o escribes ./mvnw spring-boot:run
Tú: "Al arrancar, un componente que programé llamado 'DataSeeder' inicializa las tablas e inyecta automáticamente 21 productos de ferretería, clientes y proveedores para tener datos listos de prueba."

Escena 2: Interfaz Web Integrada y Kárdex (ERP)

En Pantalla: Cambias la vista a Google Chrome, entrando a http://localhost:8080/ (la ruta raíz).
Tú: "Aunque el objetivo principal era construir el Backend, desarrollé un módulo de Interfaz Gráfica para tener un ERP funcional. Aquí vemos el Panel Principal que muestra el inventario valorizado."
Acción: Haces clic en el menú "Kárdex / Entradas". Seleccionas un producto en la tabla inferior de "Consultar Bitácora".
Tú: "Implementé un sistema de auditoría estricto. En este Kárdex puedo realizar ingresos de compra, registrar salidas manuales por merma, y consultar el historial absoluto de cada producto, con su costo unitario y precio de venta."
Acción: Haces clic en "Punto de Venta". Muestras cómo funciona la lista desplegable. Llenas una venta y le das "Confirmar". (Saltará la alerta nativa "Venta completada").
Tú: "En el Punto de Venta tuvimos un reto de Recursión Infinita con Java y JSON, que logré resolver bloqueando la recursión cíclica con anotaciones. Ahora, al realizar una venta..."
Acción: Clic en Aceptar en la alerta. Luego clic rápido en "Resumen (Inicio)" para mostrar cómo los números cambiaron.
Tú: "...el sistema confirma la transacción y, de manera asíncrona, actualiza al instante nuestras unidades y valor en Quetzales sin necesidad de recargar la página."

Escena 3: Pruebas a bajo nivel en Swagger (Kárdex y Transacciones)

En Pantalla: Cambias de pestaña en Chrome, entrando a http://localhost:8080/swagger-ui.html
Tú: "Ahora, para demostrar cómo funciona el motor por detrás, utilicé Swagger, el cual auto-documenta mi código de Java. Vamos a hacer una prueba a bajo nivel: El manejo de inventario. En este sistema, el stock no se puede alterar a mano. Se hace a través del Kárdex."
Tú: "Voy al endpoint de 'Entradas', y haré una petición para comprar 50 unidades del producto 1, que es un martillo."
Acción: Abres POST /api/entradas. Presionas 'Try it out'. Pones el JSON con 50 de cantidad y le das a 'Execute'.
Tú: "El sistema me devuelve un código 201 Created. Ahora, si voy a revisar el Kárdex de ese producto específico..."
Acción: Vas a GET /api/productos/1/kardex y le das a Execute.
Tú: "...podemos ver que la bitácora registró perfectamente que el stock anterior era 0, y el nuevo stock es 50, auditando la compra."

Escena 3: Pruebas de Facturación y Transacciones

En Pantalla: Sigues en Swagger, pero ahora bajas a la sección de Ventas.
Tú: "Ahora hagamos una venta. Uno de los puntos clave del sistema es el uso de transacciones con la anotación de base de datos '@Transactional'. Si intento vender, el sistema descuenta el stock y calcula el IVA del 12%."
Acción: Abres POST /api/ventas. Presionas 'Try it out' y envías una venta de 5 unidades.
Tú: "Aquí vemos la factura generada exitosamente. Sin embargo, si yo intentara vender 9,000 unidades de un producto, la anotación transaccional aborta la operación completa para no corromper la base de datos, lanzando un error de que el stock es insuficiente."

Escena 4: Calculadora y Valor Agregado

En Pantalla: Vas a la sección de Calculadora y Reportes en Swagger.
Tú: "Como valor agregado, le implementé a la ferretería una calculadora. Le mando el largo y ancho de una pared en metros..."
Acción: Ejecutas POST /api/calculadora/pintura mandando 10 de largo y 5 de ancho.
Tú: "...y el sistema me responde en JSON que necesito comprar 2 galones de pintura, y me sugiere automáticamente las pinturas que hay actualmente en bodega."

Escena 5: Reflexión Final y Errores Solucionados

En Pantalla: Vuelves a la cámara o muestras la estructura de tu código en IntelliJ.
Tú: "Para finalizar, quiero responder a lo solicitado en el informe. Lo que más reforcé fue la Arquitectura de Capas. Al venir de Node.js, donde los controladores y rutas se mezclan, aprender a usar Spring Boot me obligó a separar el enrutamiento web de la lógica de negocio."
Tú: "Lo que NO sabía cómo funcionaba, fue algo muy curioso. Al probar la API por primera vez, el sistema me arrojó un Error Interno 500 originado por un fallo llamado 'Carga Perezosa' o Lazy Loading. En Java, para ahorrar memoria RAM, las relaciones entre tablas no se cargan automáticamente."
Tú: "Para solucionarlo, descubrí y configuré el concepto de 'open-in-view' en las propiedades de la aplicación, lo cual le ordenó a mi sistema mantener viva la conexión a la base de datos hasta terminar de renderizar la información. Es un nivel de control de optimización que en JavaScript rara vez notamos."
Tú: "Este ha sido mi proyecto ThunderMax, muchas gracias por su atención."
